# host-guard

Лёгкий агент мониторинга сервера с уведомлениями в Telegram. Следит за нагрузкой на CPU, RAM, диск и сеть. Если показатель выше порога **всё окно наблюдения** (по умолчанию 15 минут), присылает сообщение в Telegram.

## Возможности

- Сбор метрик через `psutil`: CPU, RAM, диск, входящая и исходящая сеть
- Хранение замеров в SQLite, автоматическая очистка старых записей
- Алерт только при устойчивой нагрузке, а не при единичном скачке
- Защита от спама: про одну и ту же проблему повторно пишет не чаще, чем раз в 15 минут
- Запуск раз в минуту через cron

## Как это работает

```
cron (каждую минуту)
   -> collectors.py  снять метрики
   -> storage.py     записать в SQLite, прочитать замеры за окно
   -> checker.py     сравнить с порогами
   -> bot.py         отправить сообщение в Telegram
```

## Требования

- Linux (проверено на Arch Linux)
- Python 3.9+
- Git
- Telegram-аккаунт

## Установка

### 1. Клонируйте репозиторий

```bash
git clone https://github.com/SWAGcreator-del/host-guard.git
cd host-guard
```

### 2. Создайте виртуальное окружение и установите зависимости

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Создайте Telegram-бота и получите токен и chat_id

См. раздел «Как получить токен и chat_id» ниже.

### 4. Создайте файл `.env`

В корне проекта создайте файл `.env`:

```
TELEGRAM_TOKEN=ваш_токен_от_BotFather
TELEGRAM_CHAT_ID=ваш_chat_id
```

Без кавычек и без пробелов вокруг `=`. Файл уже в `.gitignore`, в репозиторий он не попадёт. На сервере дополнительно ограничьте доступ:

```bash
chmod 600 .env
```

### 5. Настройте пороги

**Пороги нагрузки** находятся в начале файла `monitor/checker.py`:

```python
CPU, NET_RECV, NET_SENT, MEMORY, DISK = 80.0, 12.95, 12.95, 50.0, 450.0
```

| Параметр | Что означает | Единицы |
|---|---|---|
| `CPU` | загрузка процессора | % |
| `NET_RECV` | входящий трафик | Мбит/с |
| `NET_SENT` | исходящий трафик | Мбит/с |
| `MEMORY` | занятая оперативная память | ГБ |
| `DISK` | занятое место на диске `/` | ГБ |

**Время и хранение** задаются в начале файла `monitor/main.py`:

```python
WINDOW_MINUTES = 15    # окно наблюдения: нагрузка должна держаться всё это время
COOLDOWN_MINUTES = 15  # не повторять алерт про ту же проблему чаще
KEEP_HOURS = 2         # сколько часов хранить замеры в базе
```

Подберите значения под ваш сервер. Например, для сервера с 16 ГБ RAM порог `MEMORY` разумно поставить около 12-14.

### 6. Проверьте запуск вручную

Запускайте из корня проекта, именно так (с `-m`):

```bash
python -m monitor.main
```

Ошибок быть не должно. Появится папка `data/` с файлом `metrics.db`. Проверить, что замер записался:

```bash
sqlite3 data/metrics.db "SELECT * FROM logs;"
```

### 7. Запустите по расписанию через cron

```bash
crontab -e
```

Добавьте строку (замените путь на свой):

```
* * * * * cd /home/user/host-guard && .venv/bin/python -m monitor.main >> /tmp/host-guard.log 2>&1
```

Проверка, что всё работает:

```bash
tail /tmp/host-guard.log
sqlite3 data/metrics.db "SELECT COUNT(*) FROM logs;"
```

Число записей должно расти примерно на единицу в минуту.

> Если cron не запускается (например, на Arch Linux), включите службу: `sudo systemctl enable --now cronie`

## Как получить токен и chat_id

### Токен бота

1. Откройте Telegram и найдите **@BotFather** (официальный бот с галочкой).
2. Отправьте команду `/newbot`.
3. Введите имя бота (любое, например `My Server Monitor`).
4. Введите username бота, он должен заканчиваться на `bot` (например, `my_server_monitor_bot`).
5. BotFather пришлёт сообщение с токеном вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`. Это и есть `TELEGRAM_TOKEN`.

Токен можно посмотреть позже: `/mybots`, выберите бота, **API Token**. Если токен случайно попал в чужие руки, команда `/revoke` выдаст новый.

> **Токен это пароль бота.** Не публикуйте его, не вставляйте в код и не отправляйте в чаты.

### chat_id

`chat_id` это адрес чата, в который бот будет присылать сообщения.

1. Найдите **своего бота** в Telegram по username из предыдущего шага.
2. Нажмите **Start** и отправьте боту любое сообщение, например `привет`. Пока вы не напишете боту первым, он не сможет писать вам.
3. Откройте в браузере адрес (подставьте свой токен, без скобок и пробелов):

   ```
   https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates
   ```

4. В ответе найдите блок `"chat"`:

   ```json
   "chat": { "id": 123456789, "type": "private", ... }
   ```

   Число после `"id"` это ваш `TELEGRAM_CHAT_ID`.

**Если в ответе `"result": []`:** вы ещё не написали боту, или написали не тому боту. Отправьте ему сообщение и обновите страницу.

**Если ошибка `404 Not Found`:** неверный токен в адресе. Проверьте, что после слова `bot` сразу идёт токен, без `/`, пробелов и скобок `< >`.

**Уведомления в группу:** добавьте бота в группу, напишите там сообщение и откройте `getUpdates`. У групп `chat_id` отрицательный (например, `-1001234567890`), его тоже вставляйте в `.env`.

### Проверка бота

Отправьте тестовое сообщение:

```bash
python -m monitor.bot
```

Сообщение из `bot.py` должно прийти в Telegram.

## Структура проекта

```
host-guard/
├── monitor/
│   ├── collectors.py   # сбор метрик (psutil)
│   ├── storage.py      # SQLite: запись, чтение, очистка, журнал алертов
│   ├── checker.py      # проверка порогов
│   ├── bot.py          # отправка сообщений в Telegram
│   └── main.py         # один проход: собрать, записать, проверить, отправить
├── data/               # база данных (не попадает в Git)
├── .env                # токен и chat_id (не попадает в Git)
└── requirements.txt
```

## Частые проблемы

| Проблема | Решение |
|---|---|
| `ModuleNotFoundError: No module named 'monitor'` | Запускайте из корня проекта командой `python -m monitor.main`, а не `python monitor/main.py` |
| `ModuleNotFoundError: No module named 'dotenv'` | Активируйте `.venv` и выполните `pip install -r requirements.txt` |
| Сообщения не приходят | Проверьте `.env`, напишите боту первым, запустите `python -m monitor.bot` |
| Алерт не срабатывает | Нужно минимум 10 замеров в окне наблюдения, подождите около 10 минут после запуска |
| `error: externally-managed-environment` | Вы не в виртуальном окружении, выполните `source .venv/bin/activate` |
